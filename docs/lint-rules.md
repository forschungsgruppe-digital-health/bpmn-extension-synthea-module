# Lint rules

The `synthea:` extension is checked by 33 lint rules. They catch what the BPMN XSD cannot: the XSD does not cover `<extensionElements>`, so a state without its configuration, a probability sum over 1 or a half-filled code is valid XML and still a broken pathway. All checks that run in `npm run validate` are listed in [validator-overview.md](validator-overview.md); the mapping the rules protect is in [implicit-rules.md](implicit-rules.md).

- **Where:** `extension/lint/bpmnlint-plugin-synthea/rules/`, one file per rule. The comment at the top of each file is the long explanation.
- **Enabled by:** `.bpmnlintrc` extends `plugin:synthea/all`. The severity of each rule is set in the plugin's `index.js` (`configs.all.rules`).
- **Run:** `npm run lint:valid` (the fixtures in `examples/valid/` and `examples/lung-cancer/` must pass) and `npm run lint:invalid` (`examples/invalid/` must keep failing, so the rules are proven to fire).
- **Severity:** an **error** fails the lint and so `validate`; a **warning** is reported but does not change the exit code. Warnings are used where the diagram only suggests a mistake.
- **Names:** the table names the types of the model (`synthea:StateTypeConfig`); in the XML the element starts with a small letter (`<synthea:stateTypeConfig>`).
- **Add a rule:** a file in `rules/`, an entry in `index.js` in `rules` **and** in `configs.all.rules`, a fixture in `examples/valid/` and a case in `examples/invalid/`.

| ID | Rule | Severity | Group | What it checks |
|---|---|---|---|---|
| SYN-13 | `guard-state-requires-guard-config` | error | Required fields | a `Guard` state has a `synthea:GuardConfig`; without it there is nothing to wait for |
| SYN-14 | `guard-allow-requires-condition` | error | Required fields | the `allow` condition of a `GuardConfig` is not empty (`conditionType` set; And, Or, At Least and At Most also need a non-empty list of conditions) |
| SYN-15 | `callsubmodule-requires-submodule-config` | error | Required fields | a `CallSubmodule` state has a `synthea:SubmoduleConfig` with a non-empty submodule, otherwise the call has no target |
| SYN-17 | `delay-requires-shape` | error | Required fields | a `Delay` state has a `synthea:DelayConfig` with a shape: exact, range or distribution |
| SYN-23 | `delay-range-requires-high-value` | error | Required fields | a delay of shape `RANGE` has `delayValueHigh` next to `delayValue` |
| SYN-20 | `counter-requires-action` | error | Required fields | a `Counter` state has a `synthea:CounterConfig` with attribute and action (increment or decrement); the amount is optional, default 1 |
| SYN-21 | `set-attribute-requires-attribute` | error | Required fields | a `SetAttribute` state has a `synthea:SetAttributeConfig` with an attribute name; the value is optional |
| SYN-29 | `value-range-requires-high-value` | warning | Required fields | a `synthea:ValueConfig` of shape `RANGE` has `valueHigh`; an `EXACT` value has none (Observation, Symptom, Death) |
| SYN-30 | `careplan-activity-requires-code-and-display` | warning | Required fields | each activity of a `CarePlanStart` has a SNOMED code and its display text; the system is fixed to SNOMED-CT |
| SYN-31 | `state-code-complete` | warning | Required fields | a clinical code (`codeSystem`, `code`, `codeDisplay` on `synthea:StateTypeConfig`) is complete once one part is set, and in a system the state type accepts (`extension/src/converter/codes.mjs`); otherwise the converter drops it and the state lacks the `codes` Synthea requires |
| SYN-12 | `negate-requires-condition` | error | Conditions and gateways | `negate="true"` sits on a condition with a `conditionType`. Synthea has no negate flag; the converter writes a `Not` condition around it ([implicit-rules.md](implicit-rules.md), section A) |
| SYN-16 | `probability-sum-valid` | error | Conditions and gateways | fixed probabilities on the outgoing flows of one gateway sum to at most 1, and at most one flow omits its probability (it takes the remainder); flows with a probability attribute count as neither |
| SYN-27 | `gateway-branches-require-condition-or-probability` | warning | Conditions and gateways | on an exclusive gateway with several outgoing flows each flow has a `synthea:conditionConfig` or a `synthea:probabilityConfig`; the BPMN `name` and `conditionExpression` are only labels. At most one flow has neither: the fallback (default flow) or the probability remainder |
| SYN-34 | `unique-element-names` | error | Conditions and gateways | no two named elements in one process or sub-process have the same name. Synthea identifies states by name and the state name is the BPMN label, so a duplicate would be renamed by the converter (`STATE_NAME_DUPLICATE`) and no longer match the diagram. Start events (always `Initial`), link events and documentation-only elements are not counted; no other element may be called `Initial` |
| SYN-35 | `exclusive-gateway-requires-default-flow` | error | Conditions and gateways | an exclusive gateway whose branches have a `synthea:conditionConfig` has a default flow (`default` on the gateway) and that flow has no condition. Without it Synthea ends the pathway in its default Terminal state when no condition is true (`TRANSITION_NO_FALLBACK`). Probability gateways are not affected |
| – | `inclusive-branches-require-condition-or-probability` | warning | Conditions and gateways | every branch of an inclusive gateway has its own condition or probability, because each branch is decided on its own (`extension/src/converter/gateways.mjs`); unlike the exclusive gateway there is no fallback branch |
| SYN-32 | `alternatives-not-mixed` | warning | Conditions and gateways | fields that are alternatives are not mixed (the panel clears the other field, this catches hand-edited files): fixed probability with probability attribute; more than one of value, value attribute and distribution on `SetAttribute`; `delayValueHigh` on an exact delay; `valueHigh` on an exact value; wellness with an encounter class; a code with a `referencedByAttributeConfig` |
| SYN-19 | `wellness-consistent-within-encounter` | error | Encounter | `wellness` is the same on every member of an encounter group (same `encounterId` within one process) |
| SYN-25 | `encounter-class-consistent-within-encounter` | warning | Encounter | the encounter class is the same on every member of the group and set for every non-wellness encounter |
| SYN-28 | `encounter-code-complete-and-consistent` | warning | Encounter | `encounterCodeSystem`, `encounterCode` and `encounterCodeDisplay` come together or not at all, and every member of the group agrees; Synthea requires `codes` on every non-wellness encounter |
| SYN-18 | `encounter-reference-requires-condition-or-allergy-context` | warning | Encounter | `targetEncounter` of a `synthea:EncounterReference` is used only on `ConditionOnset` and `AllergyOnset` |
| SYN-26 | `attribute-name-lower-snake-case` | warning | Attributes | attribute names are `lower_snake_case`; format only, not uniqueness across files (the lung cancer files share names on purpose; `npm run check:attributes` lists them) |
| SYN-22 | `assign-to-attribute-requires-valid-state` | warning | Attributes | `assign_to_attribute` sits only on `ConditionOnset`, `AllergyOnset`, `MedicationOrder`, `CarePlanStart` and `Device` |
| SYN-33 | `referenced-by-attribute-requires-valid-state` | warning | Attributes | `referenced_by_attribute` sits only on `ConditionEnd`, `AllergyEnd`, `MedicationEnd`, `CarePlanEnd`, `DeviceEnd` and `Death` |
| SYN-24 | `referenced-by-attribute-matches-assign` | warning | Attributes | a referenced attribute is assigned somewhere in the same process (presence only, not order in the flow); an end state finds its onset through the shared name, so a typo breaks the link silently |
| SYN-38 | `time-unit-valid` | error | Values | a unit of time is `years`, `months`, `weeks`, `days`, `hours`, `minutes` or `seconds` (lower case): the unit of a Delay, a prescription's dosage period and duration, an Age condition, and the value of a Death or Procedure state. The unit of an Observation value is a unit of measurement and is not checked |
| SYN-39 | `condition-values-valid` | error | Values | the operator fits the condition type (`==`, `!=`, `<`, `>`, `<=`, `>=`; Attribute and Observation also `is nil`, `is not nil`); gender is `M` or `F`; race and socioeconomic status are one of the wiki's names; `At Least` and `At Most` are between 1 and the number of sub-conditions; a Date has year or month, not both; an age is not negative |
| SYN-40 | `number-ranges-plausible` | warning | Values | a probability, a probability default and a reaction severity are between 0 and 1; a range does not run backwards (delay, value, distribution); a Gaussian distribution has a standard deviation of at least 0 and min <= max, an exponential one a mean above 0; refills are not negative, a dosage amount, frequency and period above 0. Left out on purpose: a Symptom value of 0 to 100, which the wiki states but Synthea's own lung cancer module breaks (250, 350) |
| SYN-41 | `code-format-plausible` | warning | Values | a code has the shape of its system: SNOMED CT 6 to 18 digits, LOINC digits, a hyphen and a check digit, RxNorm and CVX digits; a DICOM modality 2 to 4 capital letters, a SOP class an object identifier. Shape only, no lookup |
| SYN-42 | `no-delay-after-death` | warning | Values | no Delay or Guard follows a Death state in the flow: Synthea carries on after a death in the same time step, so a wait behind it can give records with a time stamp after the death |
| SYN-43 | `observation-condition-needs-observation` | warning | Values | an Observation condition that compares a value (not `is nil` / `is not nil`) reads an observation that some Observation state of the diagram records; otherwise only another module can have recorded it, and Synthea raises an exception when nobody did |
| SYN-36 | `converter-errors` | error | Converter | everything the converter (`extension/src/converter`) rejects, checked on the diagram before the conversion, with the converter's code in front of the message (`[REQUIRED_FIELD_MISSING]`): a state type it cannot determine, a field Synthea requires that is missing (strict, as in `convert:check`), elements GMF has no equivalent for (boundary events, loop markers), unstructured parallel or inclusive gateways, mixed probabilities and conditions, an encounter that cannot be formed, links and documentation-only elements that do not fit. Not checked: that called sub-modules exist (other files) |
| SYN-37 | `converter-warnings` | warning | Converter | the converter's warnings, same messages and codes: ignored configuration, an encounter order Synthea may reject, an end state without its start. Left out: `INITIAL_WITHOUT_WAIT`, which needs to know whether another module calls this one |

## Converter checks as lint

SYN-36 and SYN-37 run the converter's own checks (`checkDefinitions` in `extension/src/converter/convert.mjs`) on the diagram, so the lint cannot fall behind the converter: what the converter rejects, the lint reports first. Problems another rule already owns are left out (`STATE_NAME_DUPLICATE` is SYN-34, `TRANSITION_NO_FALLBACK` is SYN-35).

They need this repository (the converter is not part of the published `extension/` folder), so they sit in their own config, `plugin:synthea/converter`, next to `plugin:synthea/all`; `.bpmnlintrc` extends both. An installed copy of the extension uses `all` only. `extension/test/lint-contract.test.mjs` holds the contract: diagrams with one converter error each must produce the same code in the lint.
